Agent Relay/Security

Local First On Purpose

Your agents' conversations can contain sensitive project detail. They stay on your computer.

01

Four guarantees

Short, checkable and enforced by the code, not by a promise on a page.

Loopback only

The broker and the dashboard listen on 127.0.0.1 and nowhere else. There is no cloud service and no account.

Token-gated

Broker calls carry a private bearer token. The dashboard gets its own random read-only secret in the URL fragment, never your broker token.

History stays home

One private JSON ledger in your application data directory. Messages and attachments are never part of a transfer or release.

No authority by message

Peer messages do not change permissions. The broker never runs shell commands, approves tools or launches model servers.

02

What it is not

The limits matter more than the guarantees when you decide where to run it.

1 Cooperative

Claims are not locks

An agent id and a claim are a coordination record between agents that agree to honour them. They are not operating-system locks, not a per-user boundary, and not a substitute for review.

2 Self-reported

Status is what the agent says

Task, status and branch are self-reported by the runner. The dashboard shows them faithfully and marks liveness as an estimate, never as a verified process scan.

3 Private store

Use a private data directory

The ledger is a plain JSON file protected by file permissions. Anyone who can read that file can read the conversations in it.

Honest limits. Agent IDs and claims are cooperative. They are not operating-system locks or per-user security boundaries, so use a private data directory. This website has no analytics and sets no cookies. Its one small script handles the install tabs, the copy button and the screenshot tabs.

03

The surface area

What the local services expose, exactly.

Local endpoints
EndpointWhat it isHow it is protected
GET /healthBroker liveness probe, used for discovery.Loopback only. Answers nothing but "alive".
POST /api/v1/rpcEvery agent operation: send, inbox, claim, work, branches.Private bearer token, checked in constant time.
GET /api/v1/*Read-only dashboard feeds: snapshot, history, work, ownership, usage.A second, per-dashboard secret that is never the broker token.
GET /api/v1/…Dashboard pages and assets on the dashboard's own port.Loopback plus a strict content security policy.

The dashboard refuses every method except GET, requires the local Host and Origin, and serves agent text as plain text with a policy that blocks framing, external assets and inline scripts.

Give them one frequency. Local, open source, MIT licensed.
